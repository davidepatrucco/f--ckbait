# apps/website — static per-brand site generator

> Status: **scaffolding**. Generates simple static marketing pages (landing,
> pricing, FAQ) per brand from `brands/<brand>/brand.json`. No build toolchain,
> no dependencies beyond Node's stdlib.

## Layout

```
apps/website/
├── generate-site.mjs      # generator (Node ESM, stdlib only)
├── template/              # source templates with {{placeholders}}
│   ├── landing.html
│   ├── pricing.html
│   └── faq.html
├── dist/                  # generated output (git-ignored: repo-wide dist/ rule)
│   └── <brand>/{landing,pricing,faq}.html
└── README.md
```

`dist/` is ignored by the repository `.gitignore` (`dist/` rule). It is a build
artifact and is regenerated by the command below; it is not committed.

## Usage

Run from anywhere (paths are resolved relative to the script location):

```bash
# single brand
node apps/website/generate-site.mjs lemonsqueezer

# all brands that have a brand.json under brands/
node apps/website/generate-site.mjs --all

# pin the footer year for reproducible output
BUILD_YEAR=2026 node apps/website/generate-site.mjs lemonsqueezer
node apps/website/generate-site.mjs --year=2026 scout
```

Output goes to `apps/website/dist/<brand>/`.

## Placeholders

Templates use `{{key}}` tokens. The generator fills them from `brand.json`:

| Placeholder        | Source in brand.json                | Fallback              |
|--------------------|-------------------------------------|-----------------------|
| `{{displayName}}`  | `displayName`                       | `id`                  |
| `{{storeName}}`    | `storeName`                         | `displayName`         |
| `{{tagline}}`      | `tagline`                           | `""`                  |
| `{{storeSummary}}` | `store.summary`                     | `""`                  |
| `{{wordmarkPre}}`  | `wordmark.pre`                      | `""`                  |
| `{{wordmarkAccent}}`| `wordmark.accent`                  | `displayName`         |
| `{{primary}}`      | `tokens.colors.primary`             | `#000000`             |
| `{{primary700}}`   | `tokens.colors.primary700`          | `primary`             |
| `{{black}}`        | `tokens.colors.black`               | `#0D1117`             |
| `{{white}}`        | `tokens.colors.white`               | `#FFFFFF`             |
| `{{gray100}}`      | `tokens.colors.gray100`             | `#F2F4F7`             |
| `{{radius}}`       | `tokens.radius`                     | `12px`                |
| `{{fontSans}}`     | `tokens.fontSans`                   | `system-ui, sans-serif`|
| `{{privacyUrl}}`   | `urls.privacy`                      | `#`                   |
| `{{termsUrl}}`     | `urls.terms`                        | `#`                   |
| `{{supportUrl}}`   | `urls.support`                      | `#`                   |
| `{{year}}`         | `--year=` / `BUILD_YEAR` / system   | current year          |

All substituted values are HTML-escaped (`&`, `<`, `>`, `"`).

## Behavior notes

- **Deterministic**: for a fixed `brand.json` and fixed year, output is
  byte-identical across runs.
- **Missing `brand.json`**: exits with code `1` and a message naming the expected
  path.
- **Unmapped placeholders**: if a template contains a `{{token}}` the generator
  does not know, the token is left verbatim in the output and a `WARN` line lists
  it (so template/generator drift is visible). Non-fatal.

## Adding a brand

1. Create `brands/<brand>/brand.json` following the existing structure
   (`lemonsqueezer`, `scout`).
2. Run `node apps/website/generate-site.mjs <brand>`.
